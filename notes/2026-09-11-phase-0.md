## The one real technical unknown, and what it turned out to be

Running Piper warm required knowing where one utterance's PCM ends in a
headerless stream. Three empirical findings, all of which changed the design —
written up in [experiments/piper-framing.md](../experiments/piper-framing.md):

1. Piper's `audio=` figure is **cumulative**, not per-utterance.
2. stdout **must be drained concurrently** — Piper writes PCM before it logs,
   so waiting for the marker first deadlocks on anything over 64 KB.
3. `--sentence_silence` padding is **excluded from the reported duration**, so
   it silently desynchronises the stream. Running with `0` and doing our own
   inter-sentence pacing makes the framing byte-exact.

Worth recording because none of it is documented, and all three would have
produced a daemon that worked in testing and drifted in real use.

## Deviations from the plan, and why

**paplay is per-utterance, not persistent.** [01-architecture](../docs/01-architecture.md)
describes a persistent paplay. There's no way to flush a running paplay's
buffer, so instant barge-in requires killing it — and paplay costs ~15 ms
against Piper's 233 ms model load, so the warm-process argument doesn't apply.
Piper stays warm; paplay doesn't.

**Keybinds moved to `SUPER+ALT`.** All three proposed bindings collide with
Omarchy webapp defaults: `SUPER+SHIFT+S` is Google Maps, `+X` is X, `+B` is
Browser. Now `SUPER+ALT+P` (toggle), `+X` (shut up), `+V` (verbosity), with
`+B` reserved for Phase 1's brief. Nothing was unbound or overridden.

**`ack` added to the socket contract.** Opt-in: an intent carrying
`"ack": true` gets one JSON line back when it's spoken, interrupted or
dropped-with-reason. Everything without it stays fire-and-forget exactly as
specified. This is what lets `prometheus off` hear its own confirmation before
the daemon is stopped, and what makes the acceptance suite able to assert
anything at all.

**Sample rate is per-voice.** Piper voices are not all 22050 Hz, and the rate
drives both the framing maths and playback pitch. Read from the model's sidecar
JSON rather than assumed — this would have broken quietly the first time a
second voice at a different rate was chosen.

## Added at Nick's request mid-session

**Ample logging.** Two sinks, independently levelled: human-readable to the
systemd journal, structured JSONL to `~/.local/state/prometheus/prometheusd.log`.
Every intent gets an id and is logged received → accepted/dropped-with-reason →
spoken-with-timings/interrupted. **When something doesn't speak, the log says
which gate stopped it** — that was the design goal.

**A transcript of both directions.** `~/.local/state/prometheus/transcript.jsonl`
records everything said *by* the system (with timings, and dropped intents with
their reason) and everything said *to* it. The input half needs
`prometheus-capture-dictation` wired into voxtype's `[output.post_process]` —
built and ready, deliberately not enabled, since that sits in the live dictation
path.

## Measured, not asserted

| | Target | Measured |
|---|---|---|
| Time to first sound | better than 310 ms | **48–93 ms** |
| Shut-up latency | ~100 ms | **1–19 ms** |
| Stop after mic goes live | ~200 ms | **2–16 ms** |
| Ten rapid calls | never overlap | **max 1 concurrent paplay**, 745 samples |
| RAM, on and idle | < 150 MB | **117 MB** |
| CPU + context switches, idle | ~0 | **0.000 s, 0 switches** |
| Processes when off | 0 | **0** |

The zero context switches over a ten-minute idle window is the number that
proves the no-polling rule holds — every thread is genuinely blocked on a read.

13 of 13 automatable acceptance criteria pass (`experiments/run-acceptance.sh`).

## Task 0.10 — the second voice, settled

Six candidates auditioned against `alan` back to back. Nick chose
**`en_GB-alba-medium`** for the `claude` category. Two voices measure **217 MB**
against the 250 MB two-voice budget; the acceptance suite still passes 13/13.

Two things the audition surfaced that are worth keeping:

- The model metadata carries **no gender field**, so the characterisations I
  offered ("British female", "Scottish female") were inferred from dataset
  names, not verified. Said so at the time; worth not repeating as fact.
- **`en_GB-semaine-medium` is a four-speaker model** (`prudence`, `spike`,
  `obadiah`, `poppy`) and the audition only ever played speaker 0. Piper takes
  `speaker_id` per utterance, but neither the audition tool nor `Voice`
  currently plumbs it through. Three unheard voices sit behind that gap if the
  choice is ever revisited.

Nick asked for an easy way back to one voice, so `voice.agent.enabled` got a
proper front end rather than staying a JSON edit:

```
prometheus voice            # which mode am I in
prometheus voice single     # everything speaks as Alan
prometheus voice dual       # back to two voices
prometheus voice set <model>
```

`single` genuinely **stops** the second Piper rather than idling it — 217 MB
back down to 117 MB — which keeps it consistent with how the main toggle
behaves. The chosen model is remembered while off, so `dual` restores it. The
edits are surgical text substitutions inside the `agent` block, because
config.json is JSONC and a parse-and-rewrite would strip every comment in it.

Written up separately in

landed outside this repo. In short: Omarchy's `Dictation.qml` hid the indicator
during transcription, Voxtype's beeps were commented out, and the floating

Voxtype** — `voxtype config schema` lists a whole `osd.*` namespace.

preference, original gtk4 visualizer retained.

It did produce the first **real** mic-gate test, against the live voxtype state
file rather than the acceptance suite's fake directory:
`cut after 1180ms of a 5364ms utterance`, paplay 1 → 0.
